# 口播训练稿

## 30 秒版

我这个项目做的是风控审核业务域的 AI Native Agent 化。它不是单点审核助手，也不是某个策略知识库，而是从未来风控审核体系的目标态出发，把审核中的知识、流程、工具、权限、证据和反馈机制，重构为 Agent 可理解、可调用、可约束、可解释、可评估、可进化的 AI 原生风控审核体系。短期看是审核提效和证据链生成，中期看是审核口径统一和质量提升，长期看是让风控审核从人工经验驱动走向 Agent 驱动、知识约束和受控反馈进化。

## 2 分钟版

我这个项目做的是互联网风控审核领域的 AI Native Agent 化。它不是某个单一策略模块的 AI 化，也不是简单做一个审核助手，而是从整个风控审核业务域的未来形态出发，思考如何把风险发现、审核研判、案件流转、知识沉淀和反馈进化这条链路 Agent 化。

传统风控审核的问题不只是审核慢，而是整个体系比较割裂：规则在规则系统里，SOP 在文档里，历史案例在工单里，专家经验在人脑里，用户行为数据在不同工具里，质检和申诉反馈又在另一套链路里。人可以靠经验把这些信息串起来，但 AI 如果只是接进来做问答，很难形成稳定的领域能力。

所以我们做的是 AI Native 的重构。领域层面，我把它拆成五条主线：风险发现与识别、审核研判与决策、案件流转与处置编排、知识沉淀与治理、受控反馈与体系进化。能力层面，底下是三大支柱：审核域知识治理、案件上下文与证据工具、Harness 约束与治理。

落到一次审核里，系统会先组装案件级上下文，包括用户历史行为、规则命中、操作日志、设备关系、历史处罚和相似案例。然后 Agent 在 Harness 约束下调用工具和审核知识，完成风险研判，输出风险类型、证据链、规则依据、建议动作、置信度和待人工确认项。这里的 Harness 不是独立安全沙箱，而是审核域的权限边界、流程边界、动作边界和人工复核边界。

最后，人工复核、质检、申诉和新风险样本会进入反馈闭环，不是直接让 Agent 自动改规则，而是经过归因、人工审核、灰度验证、效果监控和可回滚发布，推动知识、流程、工具、Harness 和评估体系持续更新。

## 5 分钟版完整口播

我这个项目做的是风控审核业务域的 AI Native Agent 化。它不是单点审核助手，也不是某个策略知识库，而是从未来风控审核体系的目标态出发，把审核中的知识、流程、工具、权限、证据和反馈机制，重构为 Agent 可理解、可调用、可约束、可解释、可评估、可进化的 AI 原生风控审核体系。

这个项目的起点不是“审核效率低”这么简单，而是整个审核体系比较割裂。规则在规则系统里，SOP 在文档里，历史案例在工单里，专家经验在人脑里，用户行为数据在不同工具里，质检和申诉反馈又在另一套链路里。人可以靠经验把这些信息串起来，但 AI 如果只是接进来做问答，很难形成稳定的领域能力。

所以我会用一张领域架构母图来讲这个项目：五条主线加三大支柱。五条主线是业务地图，分别是风险发现与识别、审核研判与决策、案件流转与处置编排、知识沉淀与治理、受控反馈与体系进化。三大支柱是能力底座，分别是审核域知识治理、案件上下文与证据工具、Harness 约束与治理。

落到一次具体审核里，系统会先调用审核域知识资产，包括规则、策略、SOP、历史案例、质检标准和申诉规则；然后组装案件级上下文，包括用户历史行为、当前触发规则、操作日志、设备关系、历史处罚和相似案例。Agent 在这个上下文里调用工具、聚合证据、对齐规则，形成风险研判。

这里最关键的是 Harness。它不是一个独立安全沙箱，而是审核域的权限边界、流程边界和动作边界。比如哪些工具可以调用，哪些数据可以读取，哪些结论只能建议不能执行，哪些高风险或低置信案件必须转人工。最终 Agent 输出的不是一句判断，而是风险类型、风险等级、核心证据、证据来源、规则依据、建议动作、置信度和待人工确认项。

长期看，每一次审核也是对体系的验证。人工复核、质检、申诉和新风险样本会形成反馈信号，这些信号不会直接写回知识体系，而是先做归因：到底是知识缺口、上下文缺口、工具缺口、Harness 边界缺口，还是评估集没有覆盖。归因之后再进入候选更新、人工审核、灰度验证、效果监控和可回滚发布。

这套体系背后需要 RAG、Tool Calling、Workflow、Prompt、Harness、Eval 和可观测性支撑，但这些技术不是主角。主角是风控审核业务域从人工经验驱动，走向 Agent 驱动、知识约束、工具协同、证据可解释和受控反馈进化。价值上，短期是审核提效和证据链生成，中期是审核口径统一和质量提升，长期是让新风险样本更快进入体系迭代。
