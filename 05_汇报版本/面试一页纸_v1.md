# 面试一页纸 v1

## 使用场景

这份材料用于面试前快速复盘，目标不是替代底稿，而是帮助你在 30 秒、2 分钟、5 分钟和追问答辩之间保持同一条主线。

## 一句话定位

这个项目做的是**风控审核业务域的 AI Native Agent 化**。

它不是单点审核助手，也不是某个策略知识库，而是把风控审核中的知识、流程、工具、权限、证据和反馈机制，重构为 Agent 可理解、可调用、可约束、可解释、可评估、可进化的 AI 原生风控审核体系。

## 核心校准

```text
AI+：
在旧流程上叠加 AI 能力，比如审核问答、摘要、推荐和辅助查询。

AI Native：
围绕 Agent 的理解、规划、工具调用、证据组织和反馈学习能力，重构业务流程、交付物、人机边界和数据闭环。

本质：
AI+ 是能力叠加；AI Native 是生产关系重构。
```

风控审核里的终态不是“模型自动处罚用户”，而是 Agent 在规则、工具和 Harness 约束下交付可审计的审核 artifact，人负责高风险裁决和反馈治理，系统通过受控反馈形成持续进化。

## 主线骨架

```text
核心矛盾：
知识、流程、工具、权限与反馈割裂
        ↓
目标态：
Agent 驱动、知识约束、工具协同、证据可解释、反馈可进化
        ↓
领域架构：
五条主线 × 三大支柱
        ↓
运行闭环：
知识资产 → 案件上下文 → Agent → Harness → 证据链 → 人工反馈 → 体系更新
        ↓
价值证明：
短期提效 / 中期提质 / 长期进化
```

## 五条主线

```text
1. 风险发现与识别：
从规则命中后才审核，走向 Agent 主动发现异常和新风险模式。

2. 审核研判与决策：
从审核员经验判断，走向证据驱动、规则对齐、置信度分层的 Agent 研判。

3. 案件流转与处置编排：
从固定工单流程，走向基于风险等级、置信度和权限边界的动态编排。

4. 知识沉淀与治理：
从经验散落在人和文档里，走向规则、案例、SOP、质检和申诉反馈的结构化治理。

5. 受控反馈与体系进化：
从人工复盘后手动改规则，走向候选生成、人工审核、灰度验证、效果监控和可回滚迭代。
```

## 三大支柱

```text
审核域知识治理：
解决规则、SOP、案例、质检标准和申诉规则如何被 Agent 消费和迭代。

案件上下文与证据工具：
解决一次 one-off 审核任务里，Agent 这次看什么、查什么、引用什么。

Harness 约束与治理：
解决 Agent 在什么权限、流程、动作和人工复核边界内运行。
```

## 运行闭环

### 单次审核闭环

```text
审核域知识资产
→ 案件级上下文组装
→ Agent 调用工具、聚合证据、对齐规则
→ Harness 限定权限、流程、动作和人工复核边界
→ 输出风险类型、证据链、规则依据、建议动作、置信度和待确认项
```

### 交付物 artifact

```text
风险类型
证据链
规则依据
建议动作
置信度与风险等级
待人工确认项
执行 trace
反馈入口
```

面试口径：Agent 不只交付一句结论，而是交付一份可审计、可复核、可追踪、可反馈的审核工作产物。

### 长期进化闭环

```text
人工复核 / 质检 / 申诉 / 新风险样本
→ 反馈归因
→ 候选知识、候选策略、候选工具或 Harness 边界更新
→ 人工审核
→ 灰度验证
→ 效果监控
→ 可回滚发布
```

### 人机边界

```text
Agent：
承担证据收集、规则对齐、初步研判、结构化交付和候选更新生成。

人：
负责目标定义、风险红线、高风险裁决、异常纠偏、候选更新审核和体系治理。
```

人的输入是审核目标、业务约束、复核意见和纠错原因；人的输出是最终裁决、处置动作、反馈标注、知识更新审核和边界调整。

## 价值表达

```text
短期提效：
减少查证步骤，提升证据链生成效率，中低风险案件更快分流。

中期提质：
统一审核口径，提升证据链完整率、规则引用准确率和人工复核质量。

长期进化：
让新风险样本更快进入知识、流程、工具、Harness 和评估体系迭代。
```

## 2 分钟口播压缩版

我这个项目做的是互联网风控审核领域的 AI Native Agent 化。它不是某个单一策略模块的 AI 化，也不是简单做一个审核助手，而是从整个风控审核业务域的未来形态出发，思考如何把风险发现、审核研判、案件流转、知识沉淀和反馈进化这条链路 Agent 化。

传统风控审核的问题不只是审核慢，而是整个体系比较割裂：规则在规则系统里，SOP 在文档里，历史案例在工单里，专家经验在人脑里，用户行为数据在不同工具里，质检和申诉反馈又在另一套链路里。人可以靠经验把这些信息串起来，但 AI 如果只是接进来做问答，很难形成稳定的领域能力。

所以我们做的是 AI Native 的重构。领域层面拆成五条主线：风险发现与识别、审核研判与决策、案件流转与处置编排、知识沉淀与治理、受控反馈与体系进化。能力层面底下是三大支柱：审核域知识治理、案件上下文与证据工具、Harness 约束与治理。

落到一次审核里，系统会先组装案件级上下文，然后 Agent 在 Harness 约束下调用工具和审核知识，完成风险研判，输出风险类型、证据链、规则依据、建议动作、置信度和待人工确认项。长期看，人工复核、质检、申诉和新风险样本会进入受控反馈闭环，经过归因、人工审核、灰度验证、效果监控和可回滚发布，推动体系持续更新。

## 高频追问防线

### 1. 和普通 RAG / Copilot 有什么区别？

普通 RAG 或 Copilot 更像问答和辅助查询；这个项目关注完整风控审核业务域的 Agent 化。RAG 只是审核域知识治理的一种实现方式，真正核心是 Agent 如何在案件上下文、证据工具和 Harness 约束下完成风险研判，并通过人工复核、质检、申诉和新风险样本推动体系进化。

### 2. Agent 会不会幻觉？

风控审核不能让模型凭感觉判断，所以事实必须来自工具、规则、日志、案例或知识资产。模型主要负责信息整合、证据组织和解释生成；输出要区分已验证事实、模型推断和待人工确认项。高风险、低置信、规则冲突或高影响处置必须进入人工复核。

### 3. Harness 到底是什么？

在这个项目里，Harness 不是独立安全沙箱，而是审核域对 Agent 的权限边界、流程边界、动作边界和人工复核边界。它定义 Agent 可以调用什么工具、读取什么数据、输出什么结论、哪些动作只能建议、哪些案件必须转人工。

### 4. 规则引擎和 Agent 是替代关系吗？

不是。规则引擎适合明确、稳定、可结构化的强规则；Agent 适合多源信息整合、语义理解、案例类比、证据解释和复杂边界判断。强规则走规则引擎，复杂判断由 Agent 辅助，模糊、高风险或低置信场景进入人工复核。

### 5. 体系进化会不会污染知识体系？

不会让反馈直接写入正式知识体系。反馈要先经过归因、候选生成、冲突检测、适用范围判断、人工审核、灰度验证、效果监控和版本回滚机制。Agent 可以生成候选知识或候选策略，但不能无约束发布。

### 6. 个人贡献怎么讲？

可以按三层讲：第一，方向和架构，参与或负责风控审核业务域 AI Native Agent 化的目标态和领域架构设计；第二，关键链路，参与或负责审核域知识治理、案件上下文、证据工具、Agent 审核链路、Harness 约束或证据链输出；第三，闭环和验证，推动人工复核、质检、申诉和新风险样本进入反馈归因与体系更新，并用指标验证提效、提质和进化价值。

## 禁用表达

```text
不要说：
做了一个审核问答助手
做了一个风控知识库
让 Agent 自动改规则
让 Agent 自动处罚用户
模型直接替代审核员
准确率提升到某个具体数字但没有真实数据

建议说：
风控审核业务域的 AI Native Agent 化
Agent 输出审核建议和证据链
高风险、低置信、高影响动作必须人工复核
反馈进入受控归因、灰度验证和可回滚发布
RAG、Tool、Workflow、Harness、Eval 都服务于业务主线
```
