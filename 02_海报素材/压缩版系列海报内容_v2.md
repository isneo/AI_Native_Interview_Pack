# 压缩版系列海报内容 v2

## 总原则

新版海报不是“标题 + 几个关键词”，而是每张都保留五类信息：

```text
本质问题：这一章到底回答什么
结构展开：把主线向下展开一层
亮点表达：面试里最容易显得有操盘感的部分
误区边界：避免把项目讲偏或讲得过度承诺
引导金句：让面试官顺着你的逻辑继续追问
```

视觉上要做到：高信息密度，但分区清晰；每张只讲一个核心问题；标题、层级、箭头和重点框要能引导阅读路径。

## poster_00｜项目定位与五层总地图

### 本质问题

这个项目不是“做了一个审核助手”，而是把风控审核业务域重构成 Agent 可运行、可约束、可解释、可评估、可进化的 AI 原生体系。

### 结构展开

```text
1. 项目定位：
风控审核业务域的 AI Native Agent 化

2. 核心矛盾：
知识、流程、工具、权限、反馈割裂

3. 领域架构：
五条主线 × 三大支柱

4. 运行闭环：
单次审核闭环 × 长期进化闭环

5. 价值证明：
短期提效 / 中期提质 / 长期进化
```

### 亮点表达

```text
以终为始：
先定义未来风控审核体系的目标态，再倒推 Agent 化改造对象。

从工具到体系：
不是给审核员多一个问答入口，而是重构知识、工具、权限、证据和反馈的协同方式。

讲业务域，不讲单点功能：
用业务生命周期组织叙事，而不是按技术模块堆叠。
```

### 误区边界

```text
不要讲成：
审核 Copilot / 风控知识库 / 单点 RAG / 模型替代审核员

应该讲成：
Agent 输出可复核审核建议，关键动作仍受 Harness 和人工复核约束。
```

### 引导金句

项目的核心不是“AI 帮人审得更快”，而是让风控审核从人工经验串联，走向 Agent 驱动、知识约束、工具协同和受控反馈进化。

## poster_01｜核心矛盾与目标态

### 本质问题

传统风控审核真正的问题不是单次审核慢，而是知识、流程、工具、权限和反馈分散在不同系统与人脑里，导致 AI 很难稳定接管复杂判断。

### 结构展开

```text
传统割裂：
规则在规则系统里
SOP 在文档里
案例在工单里
经验在审核员脑里
数据在不同工具里
质检和申诉在反馈链路外

目标态：
知识可消费
上下文可组装
工具可调用
权限可约束
证据可解释
反馈可进化
```

### 亮点表达

```text
问题诊断更深：
不是效率问题，而是领域能力组织方式的问题。

目标态更稳：
AI 不是直接替代人，而是在业务边界内组织任务、查证证据、形成建议。

可控性前置：
越靠近处置、规则更新和高影响动作，越需要人工复核、灰度验证和回滚。
```

### 误区边界

```text
误区 1：
把项目讲成“减少审核员工作量”。
修正：
提效只是短期价值，真正目标是形成可持续进化的审核体系。

误区 2：
把 Agent 讲成“自动决策者”。
修正：
Agent 是受控执行者和证据组织者，不绕过强规则和人工复核。
```

### 引导金句

传统体系的问题不是缺一个 AI，而是缺一套让 AI 能读懂、能调用、能受控、能被验证的领域运行结构。

## poster_02｜领域架构母图：五条主线 × 三大支柱

### 本质问题

领域架构回答“整个风控审核业务域如何被 Agent 化改造”，五条主线是业务生命周期，三大支柱是共享能力底座。

### 结构展开

```text
五条主线：
风险发现与识别：
异常聚类、新风险模式、相似案例召回、风险线索生成

审核研判与决策：
风险点提取、规则对齐、工具查证、证据聚合、置信度分层

案件流转与处置编排：
低风险分流、中风险复核、高风险强制人工、批量关联扩展、审计留痕

知识沉淀与治理：
复核理由结构化、候选规则生成、冲突检测、适用范围标注、版本管理

受控反馈与体系进化：
误判漏判归因、评估集更新、Harness 边界更新、灰度验证、回滚

三大支柱：
审核域知识治理
案件上下文与证据工具
Harness 约束与治理
```

### 亮点表达

```text
操盘视角：
五条主线之间最重要的不是数据传递，而是反馈信号。

复用视角：
三大支柱避免每条业务线重复造知识库、工具链和权限边界。

演进视角：
风险发现、审核研判、案件流转产生的修正信号，反哺知识、工具、Harness 和评估集。
```

### 误区边界

```text
误区 1：
把五条主线讲成五个独立模块。
修正：
它们是一条风险事件生命周期，不是孤立功能列表。

误区 2：
把三大支柱讲成 RAG / Tool / Workflow 的同义词。
修正：
RAG、Tool、Workflow 是实现方式；三大支柱是领域能力抽象。
```

### 引导金句

五条主线回答业务域怎么拆，三大支柱回答能力怎么复用，运行闭环回答系统怎么持续进化。

## poster_03｜运行闭环：单次审核 × 长期进化

### 本质问题

运行闭环回答 Agent 如何完成一次审核，以及每次审核产生的人工修正、质检、申诉和新风险样本如何受控进入体系更新。

### 结构展开

```text
单次审核：
审核域知识资产
→ 案件级上下文组装
→ Agent 调用工具、聚合证据、对齐规则
→ Harness 约束权限、流程、动作、复核边界
→ 输出风险类型、证据链、规则依据、建议动作、置信度、待确认项

长期进化：
人工复核 / 质检 / 申诉 / 新风险样本
→ 反馈归因
→ 候选知识 / 候选策略 / 候选工具 / Harness 边界更新
→ 人工审核
→ 灰度验证
→ 效果监控
→ 可回滚发布
```

### 亮点表达

```text
证据驱动：
事实来自工具、日志、规则、案例和知识资产，模型负责组织与解释。

边界清晰：
高风险、低置信、规则冲突、高影响处置必须转人工。

反馈受控：
反馈不会直接写回正式体系，必须经过归因、评审、灰度和回滚。
```

### 误区边界

```text
不要说：
Agent 自动处罚用户
Agent 自动改规则
模型直接替代审核员

应该说：
Agent 输出证据链和审核建议；高影响动作必须受 Harness 与人工复核约束。
```

### 引导金句

一次审核交付的是可解释、可复核的建议；长期闭环交付的是可验证、可回滚的体系进化。

## poster_04｜技术支撑与价值证明

### 本质问题

技术不是主角，技术要回答“这套 AI 原生审核体系为什么能稳定运行、为什么能被验证、为什么能持续进化”。

### 结构展开

```text
技术映射：
RAG / 知识库：
支撑审核域知识治理，让规则、SOP、案例、质检标准可被 Agent 消费。

Tool Calling / 数据服务：
支撑案件上下文与证据工具，让 Agent 查日志、看关系、召回案例、形成证据。

Workflow / 编排：
支撑案件流转和人机协同，让低中高风险进入不同处理路径。

Harness / 权限边界：
支撑风险门控、动作边界、人工复核、审计留痕和回滚。

Eval / 回归测试：
支撑误判漏判评估、边界场景覆盖和新风险样本回归。

Observability / 可观测性：
支撑工具调用、证据来源、反馈归因和效果监控可追踪。
```

### 亮点表达

```text
价值三层：
短期提效：
审核耗时下降、查证步骤减少、证据链生成提速、中低风险分流。

中期提质：
审核口径统一、证据链完整率提升、规则引用准确、人工复核质量提升。

长期进化：
新风险样本更快回流，知识、流程、工具、Harness 和评估集持续更新。
```

### 误区边界

```text
误区 1：
只讲用了 RAG、Tool、Workflow。
修正：
先讲业务主线，再讲技术如何支撑。

误区 2：
没有真实数据时讲具体提升比例。
修正：
用指标框架表达，不编造百分比。

误区 3：
只看模型效果。
修正：
同时看效率指标、质量指标和体系指标。
```

### 引导金句

面试里不要把技术当清单讲，要把技术放回业务闭环里：它支撑什么主线、控制什么风险、证明什么价值。
