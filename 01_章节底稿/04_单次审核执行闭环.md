# 第 3A 章｜单次审核执行闭环

## 本章定位

本章讲运行闭环的前半段：**Agent 如何完成一次具体的审核案件。**

它不是领域架构母图，而是母图落到一次案件里的执行路径。

## 核心链路

```text
审核域知识资产
  ↓
案件级上下文组装
  ↓
Agent 化审核链路
  ↓
Harness 约束与治理
  ↓
证据链与审核建议
```

## 1. 审核域知识资产：Agent 知道什么

对应三大支柱中的：

```text
审核域知识治理
```

包括：

```text
审核规则
风控策略
SOP
历史案例
专家经验
质检标准
申诉规则
处置标准
黑产模式
反例库
```

重点不是“有一个知识库”，而是这些知识能被 Agent 理解、引用、约束和更新。

## 2. 案件级上下文组装：Agent 这次审核看什么

对应三大支柱中的：

```text
案件上下文与证据工具
```

风控审核通常是 one-off 任务。这里的上下文不是多轮对话历史，而是这一次案件需要的行为、证据和工具结果：

```text
用户历史行为
当前触发规则
当前案件触发原因
操作日志
交易记录
内容上下文
设备 / IP 关系
历史处罚
相似案例
工具查证结果
```

## 3. Agent 化审核链路：Agent 怎么做

对应五条主线中的：

```text
风险发现与识别
审核研判与决策
案件流转与处置编排
```

典型动作包括：

```text
案件理解
风险点提取
工具调用
知识调用
证据聚合
规则对齐
风险研判
置信度分层
建议生成
```

## 4. Harness 约束与治理：Agent 在什么边界内做

对应三大支柱中的：

```text
Harness 约束与治理
```

这里的 Harness 不是独立安全沙箱，而是审核域的权限边界、流程边界和动作边界：

```text
哪些工具可以调用
哪些数据可以读取
哪些策略适用
哪些结论只能建议不能执行
哪些动作必须转人工
哪些场景需要更高置信度
哪些高影响处置必须留痕和复核
```

## 5. 证据链与审核建议：Agent 最后交付什么

输出应该是可解释、可复核、可追溯的结构化结果：

```text
风险类型
风险等级
核心证据
证据来源
规则依据
建议动作
置信度
待人工确认项
转人工原因
```

## 单次执行与长期进化的接口

单次审核不是闭环终点。它会产生后续进化需要的信号：

```text
Agent 判断是否被人工采纳
证据链是否完整
规则引用是否准确
是否出现误判 / 漏判
人工修改了哪些结论
申诉是否推翻原判断
```

这些信号会进入下一章的“人机协同与体系进化闭环”。

## 一句话总结

单次审核执行闭环讲的是：Agent 如何在一次审核任务中，把知识、上下文、工具和 Harness 约束组织起来，输出可解释、可复核的审核建议。
