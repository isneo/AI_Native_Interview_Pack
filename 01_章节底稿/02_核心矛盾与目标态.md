# 第 1 章｜核心矛盾与目标态

## 本章目标

把问题从“审核效率低”升维到“风控审核体系中的知识、流程、工具、权限和反馈机制割裂”，并给出 AI 原生风控审核体系的目标态。

## 核心矛盾

传统风控审核的问题不只是审核慢，而是整个体系被拆散在不同系统、不同流程和不同人身上：

```text
规则在规则系统里
SOP 在文档里
历史案例在工单里
专家经验在人脑里
用户行为数据在不同工具里
处置权限在流程系统里
质检和申诉反馈在另一套链路里
```

人可以靠经验把这些信息临时串起来，但 Agent 如果只是接入一个问答入口，很难形成稳定、可控、可复用的领域能力。

## 为什么普通 RAG / Copilot 不够

普通 RAG 或 Copilot 主要解决“知识能不能被问到、文本能不能被生成”的问题，但风控审核还需要解决：

```text
案件上下文如何组装
证据如何被查证
规则和 SOP 如何约束判断
工具和处置权限如何受控
低置信和高风险案件如何转人工
人工反馈如何反哺体系
```

所以这个项目不是“给审核员加一个问答助手”，而是要重构风控审核业务域的运行方式。

## 目标态

AI 原生风控审核体系应该具备六个特征：

```text
Agent 驱动：
由 Agent 组织一次审核任务，而不是只回答审核员的问题。

知识约束：
规则、SOP、案例、质检标准和申诉规则成为 Agent 的领域边界。

工具协同：
用户画像、日志、图谱、规则引擎、内容理解等工具可被受控调用。

证据可解释：
每个结论绑定证据来源、规则依据、置信度和待确认项。

人工可复核：
高风险、低置信、规则冲突或高影响处置必须进入人工复核。

反馈可进化：
人工复核、质检、申诉和新风险样本能反哺知识、流程、工具、Harness 和评估体系。
```

## 目标态与后续章节关系

```text
核心矛盾
  ↓
目标态六要素
  ↓
领域架构母图：五条主线 × 三大支柱
  ↓
运行闭环：单次审核 + 长期进化
  ↓
技术支撑与价值证明
```

## 面试口播

传统风控审核的问题不是单纯审核慢，而是知识、流程、工具、权限和反馈机制割裂。规则在规则系统里，SOP 在文档里，历史案例在工单里，专家经验在人脑里，用户行为数据又散在不同工具里。人可以靠经验把这些信息串起来，但 Agent 如果只是接进来做问答，很难形成稳定的领域能力。

所以我们的目标不是做一个审核 Copilot，而是构建 AI 原生风控审核体系：让 Agent 能组织审核任务，在领域知识和 Harness 边界约束下调用工具、查证证据、形成判断，并通过人工复核、质检、申诉和新风险样本持续更新体系。
