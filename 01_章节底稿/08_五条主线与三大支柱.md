## 五条主线详解

### 1. 风险发现与识别

核心命题：

```text
从“规则命中后才审核”，走向“Agent 主动发现异常和新风险模式”。
```

Agent 化体现：

```text
异常行为聚类
新型风险模式发现
相似案例召回
多模态内容理解
风险线索生成
```

边界提醒：

```text
风险发现不等于直接处置。它输出风险线索、证据和置信度，后续仍要进入审核研判和 Harness 约束。
```

### 2. 审核研判与决策

核心命题：

```text
从“审核员经验判断”，走向“证据驱动、规则对齐、置信度分层的 Agent 研判”。
```

Agent 化体现：

```text
风险点提取
规则 / SOP 对齐
工具查证
证据聚合
置信度分层
待人工确认项输出
```

边界提醒：

```text
Agent 输出的是审核建议和证据链，不应在高风险、高影响或低置信场景里绕过人工复核。
```

### 3. 案件流转与处置编排

核心命题：

```text
从“固定工单流程”，走向“基于风险等级、置信度和权限边界的动态编排”。
```

Agent 化体现：

```text
低风险自动分流
中风险补充查证或人工复核
高风险强制人工复核
批量关联风险扩展
处置建议生成
审计链路留痕
```

边界提醒：

```text
案件流转不是简单工单分发，而是把风险判断、权限边界和人机协同流程连接起来。
```

### 4. 知识沉淀与治理

核心命题：

```text
从“经验散落在人和文档里”，走向“规则、案例、SOP、质检和申诉反馈的结构化治理”。
```

Agent 化体现：

```text
人工复核理由结构化
新风险样本归档
候选规则 / 候选案例生成
冲突检测
适用范围标注
版本管理
```

边界提醒：

```text
知识沉淀不是项目全部，它是五条主线之一。不能把整个项目讲成“AI 生产风控知识”。
```

### 5. 受控反馈与体系进化

核心命题：

```text
从“人工复盘后手动改规则”，走向“候选生成、人工审核、灰度验证、效果监控和可回滚迭代”。
```

Agent 化体现：

```text
误判 / 漏判归因
策略效果监控
候选优化建议
评估集更新
Harness 边界更新
灰度验证与回滚
```

边界提醒：

```text
受控反馈与体系进化不是让 Agent 无约束自动改规则。越靠近自治，越需要保守。
```

## 三大支柱详解

| 支柱 | 解决什么问题 | 支撑哪些主线 |
|---|---|---|
| 审核域知识治理 | 规则、SOP、案例、质检、申诉和专家经验如何被 Agent 消费和迭代 | 五条主线全部 |
| 案件上下文与证据工具 | one-off 审核任务中，Agent 这次看什么、查什么、引用什么 | 风险发现、审核研判、案件流转 |
| Harness 约束与治理 | Agent 在什么权限、流程和动作边界内运行 | 审核研判、案件流转、体系进化 |

## 协同案例模板

可以用“新型话术诈骗黑产团伙”作为示例，但要根据真实项目替换细节：

```text
1. 风险发现与识别：
Agent 发现一批账号在注册时间、设备指纹、活跃时段或内容模式上异常聚集，标记为潜在团伙风险。

2. 审核研判与决策：
Agent 调用关联图谱、行为日志、内容理解和历史案例，形成风险判断，并输出账号关联、行为模式、内容意图等证据链。

3. 案件流转与处置编排：
系统根据风险等级和置信度分流。高置信风险进入受控处置建议，中等置信进入人工复核，低置信进入观察或补充查证。

4. 知识沉淀与治理：
人工复核和处置结果被结构化为候选知识，包括触发条件、证据要求、适用范围和反例边界。

5. 受控反馈与体系进化：
候选知识经过评审、灰度验证和效果监控后，再更新到知识资产、工具编排、Harness 边界或评估集中，反哺下一轮识别和决策。
```

## 操盘者视角

如果以操盘者身份讲，重点不要只讲单条主线，而要讲清楚主线之间的接口。

推荐表达：

```text
五条主线之间最重要的不是数据传递，而是反馈信号。
人审修正了什么、案件流转改了什么、策略效果衰减了多少，这些修正信号才是系统能持续进化的燃料。
```

## 高频追问

### 1. 为什么要拆成五条主线？

因为风控审核不是单次模型判断，而是一条完整业务链路。只做风险发现，无法完成研判和处置；只做审核决策，无法沉淀经验；只做知识库，无法驱动真实流程。五条主线把风险事件的完整生命周期拆开，既能分阶段建设，也能最后形成互相强化的闭环。

### 2. 三大支柱和 RAG / Tool / Workflow 是什么关系？

RAG、Tool、Workflow 是工程实现方式，三大支柱是领域能力抽象。审核域知识治理可以用 RAG、知识库和版本管理支撑；案件上下文与证据工具需要工具调用、数据服务和证据快照支撑；Harness 约束与治理可以通过 Workflow、权限控制、风险门控和人工复核规则实现。面试时应先讲支柱，再按追问展开具体技术。

### 3. 受控反馈与体系进化会不会变成 Agent 自己改规则？

不会。体系进化不是无约束自动改规则，而是受控迭代。Agent 可以生成候选知识或候选策略，但进入正式体系前需要冲突检测、适用范围判断、人工审核、灰度验证、效果监控和版本回滚。
