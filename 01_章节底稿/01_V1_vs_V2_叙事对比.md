# 叙事方法论｜V1 传统叙事 vs V2 AI Native 终局叙事

## 本章定位

这是整个资产包的前置叙事方法论，用来回答一个问题：**同一个项目，为什么不能只按传统项目汇报方式讲，而要按 AI Native 终局叙事来讲？**

注意两种顺序要分开：

```text
材料阅读顺序：
先读 V1/V2 方法论，再进入 V2 总地图。

面试讲述顺序：
不要先讲 V1/V2 对比，直接用 V2 项目定位开场。
```

## V1：传统项目叙事

### 一句话定义

从当前业务痛点出发，围绕问题、方案、落地和收益，讲清楚做了一个什么样的风控审核 Agent 项目。

### 主线

```text
业务问题 → 我做了什么 → 系统如何工作 → 带来了什么结果
```

### 重点

```text
业务痛点
系统架构
技术实现
难点解决
业务指标
```

### 本质

V1 本质上是一个**AI 增强型审核工具 / 风控审核提效项目**的讲法。它不一定错，但容易把项目讲窄，让面试官只看到“用了大模型提升审核效率”。

## V2：AI Native 终局叙事

### 一句话定义

从未来风控审核体系的目标态出发，围绕“风控审核业务域 AI Native Agent 化、受控执行、证据可解释、反馈可进化”来讲项目。

### 主线

```text
未来要成为什么
  ↓
为什么必须重构审核体系
  ↓
今天如何建设通往目标态的能力
```

### 重点

```text
目标态
AI 原生风控审核体系
领域架构母图
Agent 化审核链路
Harness 约束与治理
案件上下文与证据工具
受控反馈与体系进化
```

### 本质

V2 本质上是在建设**风控审核业务域的 AI 原生运行体系**，而不只是做一个 Agent 工具。

## 二者本质差异

| 维度 | V1 | V2 |
|---|---|---|
| 叙事对象 | 一个审核 Agent 项目 | 整个风控审核业务域 |
| 出发点 | 当前审核痛点 | 未来审核体系应该如何运行 |
| 价值中心 | 审核提效与流程优化 | 审核体系 AI 原生化与受控进化 |
| Agent 定位 | 审核助手 / 提效工具 | 审核链路执行入口、证据组织者、反馈采集器 |
| 技术模块角色 | RAG、Tool Calling、Workflow 是主角 | 技术模块是支撑领域体系的能力 |
| 最佳用法 | 补充细节 | 作为主叙事 |

## 推荐组合方式

```text
V2 做主线：
讲终局、AI Native、领域重构、受控进化。

V1 做支撑：
讲业务痛点、技术方案、落地实现、指标效果。
```

一句话说：

```text
先用 V2 定高度，再用 V1 补证据。
```

## 面试使用提醒

面试开场不要这样讲：

```text
这个项目有 V1 和 V2 两种讲法……
```

更自然的开场是：

```text
我这个项目做的是风控审核业务域的 AI Native Agent 化。它不是单点审核助手，而是把审核中的知识、流程、工具、权限、证据和反馈机制，重构成 Agent 可执行、可约束、可解释、可评估、可进化的 AI 原生风控审核体系。
```

当面试官追问“这和普通提效项目有什么区别”时，再使用 V1/V2 对比来解释。
