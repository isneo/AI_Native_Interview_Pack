# 第 2 章｜领域架构母图

## 本章目标

用一张架构母图讲清楚：整个风控审核业务域如何被 Agent 化改造，以及五条主线、三大支柱、运行闭环之间是什么关系。

## 一句话总架构

```text
风控审核业务域 AI Native Agent 化
  =
五条业务改造主线
  ×
三大底层能力支柱
  +
单次审核与长期进化的运行闭环
```

## 架构母图

```text
目标态：AI 原生风控审核体系
Agent 驱动 / 知识约束 / 工具协同 / 证据可解释 / 人工可复核 / 反馈可进化
        ↓

```

## 五条主线：业务地图

五条主线回答的是：**风控审核领域被拆成哪些对象来改造。**

```text
风险发现与识别：
从被动规则命中，走向 Agent 主动发现异常和新风险模式。

审核研判与决策：
从人工经验判断，走向证据驱动、规则对齐、置信度分层的 Agent 研判。

案件流转与处置编排：
从固定流程分发，走向基于风险等级、置信度、处置边界的人机协同编排。

知识沉淀与治理：
从经验散落在人和文档里，走向规则、案例、SOP、质检和申诉反馈的结构化治理。

受控反馈与体系进化：
从人工复盘后手动改规则，走向候选生成、人工审核、灰度验证、效果监控和可回滚迭代。
```

## 三大支柱：能力底座

三大支柱回答的是：**所有主线共享哪些底层能力。**

```text
审核域知识治理：
规则 / 策略 / SOP / 历史案例 / 质检标准 / 申诉规则 / 专家经验
重点不是“做了 RAG”，而是知识如何被生产、沉淀、冲突处理、版本管理和迭代。

案件上下文与证据工具：
用户历史行为 / 规则命中 / 操作日志 / 设备关系 / 内容上下文 / 历史处罚 / 相似案例 / 工具调用
重点不是多轮对话记忆，而是 one-off 审核任务里的案件级上下文和可查证证据。

Harness 约束与治理：
权限边界 / 流程边界 / 动作边界 / 风险门控 / 人工复核边界
重点不是独立安全沙箱，而是审核域对 Agent 的受控执行约束。
```

## 和运行闭环的关系

```text
五条主线 × 三大支柱 = 领域架构母图
运行闭环 = 这套架构具体怎么跑
```

对应关系：

```text
审核域知识资产
= 审核域知识治理

案件级上下文组装
= 案件上下文与证据工具

Agent 化审核链路
= 风险发现与识别 / 审核研判与决策 / 案件流转与处置编排

Harness 约束
= Harness 约束与治理

反馈归因与体系更新
= 知识沉淀与治理 / 受控反馈与体系进化
```

## 60 秒白板讲解

如果要用一张图讲项目架构，我会画“五条主线 × 三大支柱”。

五条主线是业务地图，分别是风险发现与识别、审核研判与决策、案件流转与处置编排、知识沉淀与治理、受控反馈与体系进化，覆盖一个风险事件从发现、判断、处置，到经验沉淀和能力反哺的完整生命周期。

三大支柱是能力底座，分别是审核域知识治理、案件上下文与证据工具、Harness 约束与治理。知识治理负责让规则、SOP、案例和反馈可被 Agent 消费和迭代；案件上下文与证据工具负责为 one-off 审核任务提供证据；Harness 负责定义 Agent 能做什么、不能做什么、什么情况下必须转人工。

所以这个项目不是单点审核助手，而是用三大支柱支撑五条主线，把风控审核领域重构成 Agent 可执行、可约束、可解释、可评估、可进化的体系。
