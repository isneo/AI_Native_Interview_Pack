# 第 4A 章｜技术模块如何支撑主叙事

## 本章定位

本章讲技术细节如何服务主叙事。面试里不要先堆 RAG、Tool Calling、Workflow，而要先说它们分别支撑五层叙事中的哪一环。

## 技术模块与主叙事的对应关系

| 技术模块 | 不建议这么讲 | 建议这么讲 |
|---|---|---|
| RAG / 知识检索 | 我们做了规则检索 | RAG 是审核域知识治理的一种实现方式，帮助 Agent 调用规则、SOP、案例和质检标准 |
| Tool Calling | Agent 会调用工具 | Tool Calling 是案件上下文与证据工具的实现方式，帮助 Agent 查证日志、图谱、用户画像和外部证据 |
| Workflow | 我们编排了流程 | Workflow 是 Agent 化审核链路和案件流转的执行框架 |
| Prompt | 我们写了提示词 | Prompt 是任务表达、角色约束、证据要求和输出格式控制方式 |
| Harness | 我们做了安全控制 | Harness 是审核域权限边界、流程边界、动作边界和人工复核边界 |
| Eval | 我们评估模型效果 | Eval 是判断、证据、规则引用和反馈更新能否可信迭代的基础 |
| Observability | 我们记录日志 | 可观测性保证工具调用、模型判断、证据引用和人工反馈可追溯 |

## 按三大支柱归类

```text
审核域知识治理：
RAG / 知识库 / 案例库 / 版本管理 / 冲突检测

案件上下文与证据工具：
Tool Calling / 数据服务 / 日志查询 / 图谱查询 / 内容理解 / 证据快照

Harness 约束与治理：
Workflow / 权限控制 / 风险门控 / 人工复核策略 / 审计留痕
```

## 按运行闭环归类

```text
知识资产 → RAG / 知识库 / 版本管理
上下文 → 数据服务 / Tool Calling / 图谱和日志工具
Agent → Prompt / Workflow / 模型编排
Harness → 权限 / 门控 / 转人工规则
证据链 → 结构化输出 / 证据引用 / 可观测性
反馈更新 → Eval / 监控 / 回归测试 / 灰度发布
```

## 面试回答模板

当面试官追问某个技术时，按四步回答：

```text
1. 这个技术解决什么业务问题？
2. 它支撑五层叙事中的哪一环？
3. 它的关键难点和边界是什么？
4. 如何评估它是否有效？
```

示例：

```text
RAG 在这个项目里不是主角。它解决的是审核域知识治理的问题，让规则、SOP、历史案例和质检标准能够被 Agent 检索、引用和约束。难点不只是召回率，还包括知识版本、冲突规则、适用范围和证据引用准确性。评估时不能只看检索命中，而要看规则引用准确率、证据链完整率和人工复核采纳率。
```

## 一句话总结

技术模块不是主叙事。主叙事是风控审核业务域的 AI Native Agent 化，技术模块是让这套体系可执行、可约束、可解释、可评估、可进化的支撑能力。
