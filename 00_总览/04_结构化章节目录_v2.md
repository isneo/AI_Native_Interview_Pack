# 04｜结构化章节目录 v2

## 目录重构原则

新的章节目录按五层叙事组织：

```text
第一层：项目定位
第二层：核心矛盾
第三层：领域架构母图
第四层：运行闭环
第五层：价值证明
```

其中：

```text
五条主线 = 业务地图
三大支柱 = 能力底座
原执行闭环 = 系统运行路径
```

## 总体阅读路径

```text
0. 总览与使用规则
1. 叙事方法论：为什么 V2 是主线，V1 是支撑
2. V2 总地图：进入推荐主线
3. 核心矛盾：为什么必须做 AI Native Agent 化
4. 领域架构母图：五条主线 × 三大支柱
5. 单次运行闭环：一次案件如何被 Agent 审核
6. 长期进化闭环：系统如何从反馈中进化
7. 技术支撑：技术模块如何服务主叙事
8. 价值证明：指标、成果与答辩口径
9. 训练材料：口播、追问、海报、汇报版
```

## 第四层：运行闭环

### 目标

讲清楚系统不是概念图，而是如何完成一次审核，并如何长期迭代。

### 对应文件

```text
01_章节底稿/04_单次审核执行闭环.md
01_章节底稿/05_人机协同与体系进化闭环.md
```

### 单次执行闭环

```text
审核域知识资产
  ↓
案件级上下文组装
  ↓
Agent 化审核链路
  ↓
Harness 约束
  ↓
证据链与审核建议
```

### 长期进化闭环

```text
人工复核 / 质检 / 申诉
  ↓
反馈归因与体系更新
  ↓
知识资产 / 工具编排 / Harness 边界 / 评估集更新
  ↓
下一轮 Agent 审核能力提升
```

### 核心问题

```text
Agent 一次审核到底看什么、做什么、输出什么？
Harness 在运行中如何约束 Agent？
人工反馈如何进入体系，而不是只停留在纠错？
```

### 推荐输出

```text
单次审核链路图
体系进化闭环图
一个完整案件案例
```

## 第五层：技术支撑与价值证明

### 目标

把技术模块和价值指标都讲成主叙事的支撑，而不是孤立罗列。

### 对应文件

```text
01_章节底稿/06_技术模块如何支撑主叙事.md
01_章节底稿/07_价值指标与面试答辩.md
```

### 技术支撑

```text
RAG → 审核域知识治理
Tool Calling → 案件上下文与证据工具
Workflow → Agent 化审核链路
Prompt → 任务表达、角色约束和输出结构
Harness → 权限、流程、动作和复核边界
Eval → 反馈归因和体系更新的依据
Observability → 全链路可追溯
```

### 价值证明

```text
短期提效：审核耗时、证据链生成、查证成本
中期提质：口径一致、复核质量、规则引用准确率
长期进化：知识覆盖、反馈闭环、风险适应速度
```

### 推荐输出

```text
技术模块映射表
价值指标表
面试高频追问答辩库
```
